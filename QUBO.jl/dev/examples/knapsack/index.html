    Knapsack

    The Knapsack Problem is a standard benchmark for QUBO workflows because it starts from an ordinary constrained binary model and ends with a compact compiled QUBO.

    We will solve the small instance

    \[\begin{array}{r l} \max & x_{1} + 2 x_{2} + 3 x_{3} \\ \text{s.t.} & 0.3 x_{1} + 0.5 x_{2} + x_{3} \le 1.6 \\ ~ & \mathbf{x} \in \mathbb{B}^{3} \end{array}\]

    Build and Solve the JuMP Model

    using JuMP
using QUBO
using QUBOTools

model = Model(() -> ToQUBO.Optimizer(ExactSampler.Optimizer))

@variable(model, x[1:3], Bin)
@objective(model, Max, x[1] + 2 * x[2] + 3 * x[3])
@constraint(model, 0.3 * x[1] + 0.5 * x[2] + x[3] <= 1.6)

optimize!(model)

    The exact sampler is enough for this toy model, so we can inspect the optimal selection directly.

    value.(x), objective_value(model)
    ([0.0, 1.0, 1.0], 5.0)

    Inspect the Compiled QUBO

    Because QUBO.jl exposes the compiler and tooling stack together, we can also inspect the compiled QUBO representation after solving. The compiled form lives on the optimizer backend, so we retrieve it through JuMP.unsafe_backend(model).

    n, l, q, α, β = QUBOTools.qubo(JuMP.unsafe_backend(model), :dense)

(n = n, alpha = α, beta = β, nonzero_quadratic_terms = count(!iszero, q))
    (n = 8, alpha = 1.0, beta = -1792.0, nonzero_quadratic_terms = 28)

    For larger instances you would typically switch to a heuristic or hardware backend, but the modeling surface remains the same.
